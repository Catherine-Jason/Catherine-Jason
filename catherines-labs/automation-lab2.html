Automation Lab 2 - Bash System Health Check

A Bash script that checks key system health metrics on a Linux host, flags anything outside acceptable thresholds, and outputs a timestamped summary for review or log ingestion.

Overview

Keeping servers healthy requires visibility into CPU load, memory consumption, disk space, and critical service status. This script consolidates those checks into a single runnable report that can be executed manually or scheduled via cron.

Real-world relevance: Proactive system monitoring catches resource exhaustion and service failures before they become outages. This script is designed for environments where a full monitoring stack is not yet in place or a lightweight spot-check tool is needed.

Objective

  • Check CPU usage and flag if it exceeds 80 percent
  • Check memory usage and flag if used memory exceeds 85 percent
  • Check disk usage on the root partition and flag if it exceeds 90 percent
  • Verify that critical services such as SSH and cron are running
  • Output a clean, timestamped health report to the terminal and an optional log file

Script Walkthrough

  1. Set threshold variables for CPU, memory, and disk at the top of the script for easy adjustment.
  2. Used top and awk to extract current CPU idle percentage and calculate usage.
  3. Parsed free command output to calculate memory usage percentage.
  4. Used df to pull root partition disk usage percentage.
  5. Checked each critical service using systemctl is-active and captured pass or fail status.
  6. Printed a formatted summary with color-coded status indicators and appended output to a log file.

Script Preview

#!/bin/bash
# Automation Lab 2 - Bash System Health Check
# Checks CPU, memory, disk, and service status with threshold alerting

TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
LOG_FILE="/var/log/system_health.log"

CPU_THRESHOLD=80
MEM_THRESHOLD=85
DISK_THRESHOLD=90

SERVICES=("ssh" "cron")

GREEN='\033[0;32m'
RED='\033[0;31m'
RESET='\033[0m'

echo "====================================="
echo " System Health Check - $TIMESTAMP"
echo "====================================="

# CPU Usage
CPU_IDLE=$(top -bn1 | grep "Cpu(s)" | awk '{print $8}' | tr -d '%')
CPU_USED=$(echo "100 - $CPU_IDLE" | bc)
if (( $(echo "$CPU_USED > $CPU_THRESHOLD" | bc -l) )); then
    echo -e "CPU Usage:    ${RED}${CPU_USED}% - ALERT${RESET}"
else
    echo -e "CPU Usage:    ${GREEN}${CPU_USED}% - OK${RESET}"
fi

# Memory Usage
MEM_TOTAL=$(free | awk '/Mem:/ {print $2}')
MEM_USED=$(free  | awk '/Mem:/ {print $3}')
MEM_PCT=$(echo "scale=1; $MEM_USED / $MEM_TOTAL * 100" | bc)
if (( $(echo "$MEM_PCT > $MEM_THRESHOLD" | bc -l) )); then
    echo -e "Memory Usage: ${RED}${MEM_PCT}% - ALERT${RESET}"
else
    echo -e "Memory Usage: ${GREEN}${MEM_PCT}% - OK${RESET}"
fi

# Disk Usage
DISK_USED=$(df / | awk 'NR==2 {print $5}' | tr -d '%')
if [ "$DISK_USED" -gt "$DISK_THRESHOLD" ]; then
    echo -e "Disk Usage:   ${RED}${DISK_USED}% - ALERT${RESET}"
else
    echo -e "Disk Usage:   ${GREEN}${DISK_USED}% - OK${RESET}"
fi

# Service Checks
echo ""
echo "Service Status:"
for SERVICE in "${SERVICES[@]}"; do
    STATUS=$(systemctl is-active "$SERVICE" 2>/dev/null)
    if [ "$STATUS" = "active" ]; then
        echo -e "  $SERVICE: ${GREEN}Running${RESET}"
    else
        echo -e "  $SERVICE: ${RED}NOT Running - ALERT${RESET}"
    fi
done

echo "=====================================" | tee -a "$LOG_FILE"
echo "Check complete. See $LOG_FILE for history."

Key Skills Demonstrated

  • Bash scripting with conditional logic and threshold comparisons
  • Linux system resource monitoring using native command-line utilities
  • Service health verification with systemctl
  • Structured output formatting and log file management

Tools & Technologies

  • Bash (Linux shell scripting)
  • GNU Core Utilities: top, free, df, awk, bc
  • systemd (systemctl) for service management
  • Cron for scheduled execution

Results & Outcomes

  • Delivered a fast, portable system health check runnable on any standard Linux host.
  • Provided clear, color-coded output for immediate visual review during incident response or routine checks.
  • Built threshold variables at the top of the script so any team member can adjust limits without modifying logic.
  • Designed to run on a cron schedule and append results to a persistent log file for trend visibility.
