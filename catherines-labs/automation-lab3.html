Automation Lab 3: Python Log Parser and Report

Overview

When a log gets big, it is easy to miss the lines that matter. This script counts each type of event, keeps a few example lines so I know where to start looking, and lists which IP addresses have the most failed logins.

Why it matters: Many failed logins from one IP address is a sign of a brute force or password spraying attack. Finding that quickly is the same thinking I use in Splunk and in my SOC Alert Triage game.

Objective

  • Read a Linux log file line by line, with the file path given when the script runs
  • Count failed logins, invalid users, sudo commands, errors and full disk messages
  • Rank the source IP addresses with the most failed logins
  • Save a dated report and print a short summary in the terminal
  • Give a clear message instead of crashing when the file is missing or needs sudo

Script Walkthrough

  1. I listed the event types I wanted to find as regular expressions.
  2. The script takes the log path from the command line and uses /var/log/auth.log if none is given, because that is where Ubuntu writes login events.
  3. It reads the log one line at a time and checks each line against every pattern.
  4. When it finds a failed password, it pulls out the source IP and adds it to a counter.
  5. It writes a report with counts, example lines and the top IP addresses, and prints a summary.

Script Preview

#!/usr/bin/env python3
"""
Automation Lab 3: Python Log Parser and Report
Scans a Linux log for errors and security events, counts failed logins
by source IP, and saves a summary report.

Usage: python3 log_parser.py /var/log/auth.log
"""
import re
import sys
from collections import Counter
from datetime import datetime
from pathlib import Path

LOG_FILE = sys.argv[1] if len(sys.argv) > 1 else "/var/log/auth.log"
OUTPUT_DIR = Path("./reports")
PREVIEW_LINES = 5   # example lines to show for each event type
TOP_IPS = 5         # how many source IPs to list

PATTERNS = {
    "Failed login":  re.compile(r"Failed password|authentication failure", re.I),
    "Invalid user":  re.compile(r"\bInvalid user\b"),
    "Sudo command":  re.compile(r"sudo:.*COMMAND=", re.I),
    "Error":         re.compile(r"\berror\b", re.I),
    "Disk full":     re.compile(r"No space left on device", re.I),
}
FAILED_FROM_IP = re.compile(r"Failed password for .* from (\d{1,3}(?:\.\d{1,3}){3})")

matches = {name: [] for name in PATTERNS}
failed_ips = Counter()

try:
    with open(LOG_FILE, "r", errors="replace") as fh:
        for line_num, line in enumerate(fh, start=1):
            for name, pattern in PATTERNS.items():
                if pattern.search(line):
                    matches[name].append((line_num, line.rstrip()))
            ip = FAILED_FROM_IP.search(line)
            if ip:
                failed_ips[ip.group(1)] += 1
except FileNotFoundError:
    sys.exit(f"Can't find {LOG_FILE}. Check the path. Some systems only keep logs in journalctl.")
except PermissionError:
    sys.exit(f"No permission to read {LOG_FILE}. Try running it with sudo.")

timestamp = datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
lines = [f"Log Parser Report  {timestamp}", f"Source: {LOG_FILE}", "=" * 60, ""]

for name, hits in matches.items():
    lines.append(f"[{name}] {len(hits)} match(es)")
    for line_num, content in hits[:PREVIEW_LINES]:
        lines.append(f"  Line {line_num}: {content}")
    if len(hits) > PREVIEW_LINES:
        lines.append(f"  ... and {len(hits) - PREVIEW_LINES} more")
    lines.append("")

lines.append("Top sources of failed logins:")
if failed_ips:
    for ip, count in failed_ips.most_common(TOP_IPS):
        lines.append(f"  {ip}  {count} attempt(s)")
else:
    lines.append("  None found")

OUTPUT_DIR.mkdir(exist_ok=True)
output_file = OUTPUT_DIR / f"log_report_{timestamp}.txt"
output_file.write_text("\n".join(lines) + "\n")

print("Summary:")
for name, hits in matches.items():
    print(f"  {name:<14} {len(hits)}")
print("\nTop sources of failed logins:")
for ip, count in failed_ips.most_common(TOP_IPS):
    print(f"  {ip:<16} {count}")
print(f"\nFull report saved to: {output_file}")

How to Run It

  1. Save it as log_parser.py.
  2. Run sudo python3 log_parser.py /var/log/auth.log. Sudo is needed because auth.log is protected.
  3. The full report is saved in a reports folder next to the script.

Known Limits and Next Steps

  • Some newer systems keep logs only in journald. On those, run journalctl -u ssh > ssh.log first and point the script at that file.
  • The IP count only looks at SSH failed password lines.
  • A next step is flagging any IP over a set number of failures and sending that as an alert.

Version 2 Updates

I reviewed this script with help from AI tools and made these changes:

  • It now reads auth.log by default, because that is where login failures are written on Ubuntu. Reading syslog missed most of them.
  • Added the top failed login IP addresses, which turns it into a basic brute force check
  • You can pass any log file when you run it
  • It explains the problem instead of crashing when the file is missing or needs sudo
  • Lines are no longer counted twice as both a failed login and an invalid user
