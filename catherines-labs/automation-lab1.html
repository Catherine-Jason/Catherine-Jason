Automation Lab 1: PowerShell User Account Audit

Overview

Checking accounts by hand gets slow and uneven as the number of users grows. This script does the check the same way every time and saves the results in a report that says why each account was flagged.

Why it matters: Old accounts and weak password settings are an easy way in for attackers. Regular checks catch them early and support least privilege. This is also the check that catches accounts that offboarding missed, which is the problem my Click by Click Offboarding capstone works on.

Objective

  • Find enabled accounts that have not logged in for 90 days or have never logged in
  • Flag accounts where the password never expires or has already expired
  • Add a Reason column so whoever reads the report knows what to fix
  • Export the results to a dated CSV for IT and security to review

Script Walkthrough

  1. I loaded the Active Directory module and set the limit to 90 days.
  2. I used Get-ADUser to pull the enabled accounts and the fields I needed.
  3. For each account, I checked the last logon date and the password settings and wrote down every reason it needed attention.
  4. I kept only the accounts that had at least one reason.
  5. I sorted them by reason and saved them to a CSV named with the date.

Script Preview

# Automation Lab 1: PowerShell User Account Audit
# Finds enabled Active Directory accounts that are inactive or have risky
# password settings, and saves a CSV report that says why each one was flagged.

Import-Module ActiveDirectory

$DaysInactive = 90
$CutoffDate   = (Get-Date).AddDays(-$DaysInactive)
$Timestamp    = Get-Date -Format "yyyy-MM-dd"
$OutputFile   = ".\UserAuditReport_$Timestamp.csv"

$Users = Get-ADUser -Filter 'Enabled -eq $true' -Properties `
    DisplayName, LastLogonDate, PasswordNeverExpires, PasswordLastSet, PasswordExpired

$Results = foreach ($User in $Users) {
    $Reasons = @()

    if ($null -eq $User.LastLogonDate) {
        $Reasons += "Never logged in"
    }
    elseif ($User.LastLogonDate -lt $CutoffDate) {
        $Reasons += "Inactive $DaysInactive+ days"
    }
    if ($User.PasswordNeverExpires) { $Reasons += "Password never expires" }
    if ($User.PasswordExpired)      { $Reasons += "Password expired" }

    if ($Reasons.Count -gt 0) {
        [PSCustomObject]@{
            DisplayName          = $User.DisplayName
            SamAccountName       = $User.SamAccountName
            LastLogonDate        = $User.LastLogonDate
            PasswordLastSet      = $User.PasswordLastSet
            PasswordNeverExpires = $User.PasswordNeverExpires
            Reason               = $Reasons -join "; "
        }
    }
}

$Results | Sort-Object Reason |
    Export-Csv -Path $OutputFile -NoTypeInformation -Encoding UTF8

Write-Host "Audit complete. $(@($Results).Count) accounts flagged."
Write-Host "Report saved to: $OutputFile"

How to Run It

  1. Run it on a machine that has the RSAT Active Directory module, signed in with an account that can read AD.
  2. Run .\UserAudit.ps1 from PowerShell. The CSV is saved in the same folder.
  3. To run it every Monday morning, schedule it with Task Scheduler:
schtasks /create /tn "AD User Audit" /tr "powershell.exe -NoProfile -File C:\Scripts\UserAudit.ps1" /sc weekly /d MON /st 07:00

Known Limits and Next Steps

  • LastLogonDate can be up to about 14 days behind, because Active Directory does not copy it between domain controllers on every login. That is fine for a 90 day check, but not for checking yesterday.
  • Service accounts often have passwords that never expire on purpose. A next step is an exclude list so known service accounts are reviewed separately.
  • The script only reports. It does not disable anything, so a person still decides what to do with each account.
