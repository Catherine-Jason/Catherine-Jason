Automation Lab 2: Bash System Health Check

Overview

When something feels slow or broken, you need to see quickly whether the machine is under pressure or a service has stopped. This script puts those checks into one command that gives the same answer every time.

Why it matters: Spotting a full disk or a stopped service early makes it easier to fix before it turns into an outage.

Objective

  • Check CPU use and flag it above 80 percent
  • Check memory use and flag it above 85 percent
  • Check disk use on the root partition and flag it above 90 percent
  • Check that key services like SSH and cron are running
  • Print a colored report, save a plain text copy to a log, and exit with an error when something needs attention

Script Walkthrough

  1. I set the limits for CPU, memory and disk at the top so they are easy to change.
  2. I wrote a small function that prints each line in color and saves the same line as plain text for the log.
  3. I used vmstat to take two CPU samples one second apart, so the number is current use and not an average since the machine started.
  4. I used free to work out memory use, counting only memory that programs cannot use. Cache does not count as used.
  5. I used df to get the disk use on the root partition.
  6. I checked each service with systemctl is-active.
  7. I saved the whole report to a log in my home folder and made the script exit with 1 if anything was in ALERT.

Script Preview

#!/bin/bash
# Automation Lab 2: Bash System Health Check
# Checks CPU, memory, disk and key services, prints a colored report,
# saves a plain text copy to a log, and exits with 1 if anything needs attention.

CPU_THRESHOLD=80
MEM_THRESHOLD=85
DISK_THRESHOLD=90
SERVICES=("ssh" "cron")              # Debian and Ubuntu names. Fedora uses "sshd" and "crond".
LOG_FILE="$HOME/system_health.log"   # Your home folder, so no sudo is needed

GREEN='\033[0;32m'
RED='\033[0;31m'
RESET='\033[0m'
ALERTS=0
REPORT=""

# Print one line in color and save the same line as plain text for the log
check() {   # $1 = label, $2 = value, $3 = OK or ALERT
    if [ "$3" = "OK" ]; then COLOR=$GREEN; else COLOR=$RED; ALERTS=$((ALERTS + 1)); fi
    printf "%-14s ${COLOR}%s  %s${RESET}\n" "$1" "$2" "$3"
    REPORT+="$(printf "%-14s %s  %s" "$1" "$2" "$3")"$'\n'
}

TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
echo "===== System Health Check: $TIMESTAMP ====="

# CPU: two samples one second apart, so this is current use and not an average since boot
CPU_USED=$(vmstat 1 2 | tail -1 | awk '{print 100 - $15}')
if [ "$CPU_USED" -gt "$CPU_THRESHOLD" ]; then check "CPU" "${CPU_USED}%" "ALERT"; else check "CPU" "${CPU_USED}%" "OK"; fi

# Memory: counts memory that is not available to programs (cache is not counted as used)
MEM_PCT=$(free | awk '/Mem:/ {printf "%d", ($2 - $7) / $2 * 100}')
if [ "$MEM_PCT" -gt "$MEM_THRESHOLD" ]; then check "Memory" "${MEM_PCT}%" "ALERT"; else check "Memory" "${MEM_PCT}%" "OK"; fi

# Disk: root partition
DISK_USED=$(df / | awk 'NR==2 {gsub("%", "", $5); print $5}')
if [ "$DISK_USED" -gt "$DISK_THRESHOLD" ]; then check "Disk (/)" "${DISK_USED}%" "ALERT"; else check "Disk (/)" "${DISK_USED}%" "OK"; fi

# Services
for SERVICE in "${SERVICES[@]}"; do
    if systemctl is-active --quiet "$SERVICE" 2>/dev/null; then
        check "$SERVICE" "running" "OK"
    else
        check "$SERVICE" "stopped" "ALERT"
    fi
done

echo "Alerts: $ALERTS"

# Save a plain text copy (no color codes) to the log
{
    echo "===== System Health Check: $TIMESTAMP ====="
    printf "%s" "$REPORT"
    echo "Alerts: $ALERTS"
} >> "$LOG_FILE"
echo "Saved to $LOG_FILE"

# Exit 1 when something needs attention, so cron or a monitoring tool can act on it
if [ "$ALERTS" -gt 0 ]; then exit 1; fi
exit 0

How to Run It

  1. Save it as health_check.sh and make it runnable with chmod +x health_check.sh.
  2. Run ./health_check.sh. No sudo is needed because the log goes to your home folder.
  3. To run it every 15 minutes, add this line with crontab -e:
*/15 * * * * /home/labuser/health_check.sh > /dev/null 2>&1

Known Limits and Next Steps

  • The service names ssh and cron match Debian based systems like Ubuntu, Kali and Parrot. On Fedora and Red Hat they are sshd and crond.
  • It only checks the root partition. A next step is checking every mounted disk.
  • The log keeps growing. A next step is rotating it with logrotate.
